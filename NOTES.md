# Notes

- Live/Movies/Series is decided by the URL path (`/movie/`, `/series/`), everything else is Live.
- Movies and Series caches are separate files (`movies.json`, `series.json`), read when the scope opens; the Series scope holds
  ~180k rows in RAM while open (about +100 MB), released when switching back to Live.
- Ending a movie is not an error: the state goes to Stopped, not "Stream ended".
- A finished playlist load runs one compacting GC so the parse garbage does not stay in the working set.

- Favorites and the last channel use a stable key (`k:` + hash of tvg-id, name, stream id from the last URL path segment). Old URL-hash keys are swapped for it when a matching channel loads; keys with no match (e.g. VOD not opened yet) wait until that scope loads.
- Groups show as the provider wrote them with emoji/pictographs stripped and whitespace collapsed; the raw group-title is the key for saved state. Plain-m3u entries without group-title go to "Ungrouped".


- Themes: contrast checked (WCAG ratios, worst case over the theme's backgrounds). Text/accent pairs pass 4.5:1 in Light (Fg 13.6, Fg2 5.8, Fg3 4.8, Acc 5.0, Err 5.0, Warn 4.5) and Amoled (Fg 12.6, Fg2 5.6, Acc 8.2, Warn 7.0); Light borders are >= 3:1 on Bg1. Known misses, left as designed: Fg3 (placeholder/disabled) is 2.4 in Dark and 2.9 in Amoled; Err is 3.7 in Dark and 4.3 in Amoled (status dot and large text only).
- Seek slider track sits inside the dark LCD but uses the themed Well, so it is light in the Light theme.
- Overlay text (empty state, can't play) uses fixed light brushes: the video area is black in every theme.


- Playback options hotkeys: B audio, V subtitles (cycles tracks, then off), A aspect, D deinterlace. Track lists are read from LibVLC when the menu opens or a key is pressed, not on playback start (same result, no work while idle). Subtitles are matched on the language in the track name's brackets and picked automatically when LibVLC announces the tracks.
- Aspect "Fill" crops the picture to the video area's shape (LibVLC crop geometry), recalculated on resize; "Original" is 1:1 pixels. Deinterlace On uses yadif.
- Auto-reconnect (Live only, backoff 1/2/4/8/15 s): an attempt that connects and plays for 15 s starts the count over, so a flapping stream cannot retry forever. Each failing attempt itself takes a few seconds inside LibVLC, so five tries take about 55 s to give up (measured with an unreachable address).
- Keys with the popup menu open are ignored by the window handler (menu item focus), like the group list.

- B1 (gray strips in fullscreen): LibVLCSharp.WPF's VideoView hosts the video in a native window of the system class (light gray #F0F0F0); the strips were that window showing wherever LibVLC's own video window lagged behind a resize. Replaced by `VideoSurface` (own HwndHost, window class painted black) plus `OverlayWindow` (owned, transparent, moved with SetWindowPos from the host's screen rect). Resync (layout, child windows resized, repaint) runs after fullscreen enter/exit and theme switch. LibVLCSharp.WPF is no longer referenced; the core LibVLCSharp package is. IPTV_DEBUG_BG=1 paints the host magenta and the overlay cyan (translucent).
- B1 follow-up: forcing LibVLC's child video window to a new size stretched the picture after leaving fullscreen (swap chain scaled without a re-layout). Resync no longer touches it; it re-applies the aspect/scale settings instead (now and 250 ms later), which makes LibVLC recompute the letterbox.
- Reconnect also covers a pulled cable (LibVLC raises no error then): a live stream stuck in Buffering for 10 s, or with no bytes read for 20 s while 'playing', counts as dropped. After the 5 tries it waits for Windows to report the network back (one event hook, only while gave-up) and runs one more round. Not tested with a real unplugged cable here.
- Reconnect after giving up: polls every 10 s (NetworkInterface.GetIsNetworkAvailable) and starts another round of 5 tries, for at most 10 minutes; replaces the one-shot network-change event, which fires before DHCP finishes. A new channel, Stop or a successful play ends it.
- Reconnect hardening: with the cable out a connect hangs without an error, so each reconnect attempt is cut off after 15 s, and the post-give-up poll no longer requires the Error state (a late LibVLC Opening event changed the state and silently ended it). Tested with a non-routable address (hanging connects): rounds keep repeating.

- F3/F4 data model: settings.json holds a list of playlists (Id, Name, Type, DPAPI-sealed Secret, Host for display, Count, RefreshedUtc, Xtream flag). Id = hash of the source at creation; the migrated single playlist keeps the hash the old prefs used, so its groups state carried over. Favorites and the last channel moved from global settings into the per-playlist prefs. Caches live in `lists\<id>\` (playlist.json, movies.json, series.json, account.json); old files in the data folder are moved there once. Cache files no longer contain the source.
- Xtream detection: credentials from `get.php?username=&password=` in the link, else the shape `http://host:port/[live|movie|series/]user/pass/id` of the first stream URL in the cache. Logins are never stored apart from the sealed source; the account cache holds no username or password. The m3u_plus link is rebuilt from the login (output ts, else m3u8, else the first allowed format).
- Command line / drop: a file or URL is a channel list when its first 8 KB hold #EXTINF and no #EXT-X-; HLS media playlists (a single stream) are played instead. An unreachable get.php link still counts as a playlist.
- Auto-refresh covers the active playlist only. Refresh now on another playlist refreshes its caches in the background without switching. Export respects hidden groups of that playlist (compared ignoring case).
- Single instance: one mutex plus a per-user named pipe; the second launch forwards its argument (or nothing) and exits. No file association is registered: use "Open with" and pick the exe (README, T4).
- Export keeps name, tvg-id, tvg-name, tvg-logo, group-title and URL only; other attributes of the original (tvg-chno, catchup, ...) are not cached and are dropped.
- Not tested by hand: dropping a file onto the window (OLE drag from Explorer), the Xtream flow against a real server.
- F5 settings: hardware decoding, buffering and User-Agent are passed as per-media options in `Player.Play` (`:avcodec-hw`, `:network-caching`, `:http-user-agent`), so they apply from the next channel and need no LibVLC re-init. Startup modes: "Resume" plays the last channel, "List" only highlights it, "None" selects nothing (the spec listed three loosely worded options; this is the reading used). Clearing the live or VOD cache also zeroes each playlist's refreshed time so the next start fetches the list again.
- F5 mini mode: reuses the fullscreen overlay deck (window keeps its native title bar and frame, min size 460x200); the LCD strip is hidden there (too narrow), the zap OSD shows the channel. Fullscreen from mini exits mini first and returns to the normal window. Mini toggle also sits in the playback options popup; the pin button is on the deck.
- F5 diagnostics: `logs\` inside the data folder (`%LocalAppData%\YPTV`; the old `IptvPlayer` folder is moved over once at startup, T6), app.log + app.1.log + app.2.log at 1 MB, LibVLC warnings/errors and unhandled exceptions included (`--verbose=1`). Every line and the clipboard text pass `Log.Redact` (URLs -> `<url>`, absolute paths -> `<path>`). Hotkey table: `Hotkeys.cs` is the source of truth for the F1 dialog and the README (`Hotkeys.Markdown()`); dispatch in `MainWindow.Keys.cs` must be edited together with it.
- F5 not tested by hand: Ctrl+, / F1 / Ctrl+M only smoke-tested through SendKeys (dialogs open, no crash); user agent and `:avcodec-hw=none` effects on a real stream.
- T2 memory (synthetic 224k-entry playlist, framework-dependent publish, WS/Private MB): window shown 129/109 -> 82/28; LibVLC idle 180/144 -> 103/35; Live scope with 7,277 live of 224,540 entries 205/157 -> 128/45; playing the mux test stream after 60 s 226/169 -> 150/67. Cold start to a visible window ~0.3 s (unchanged). Two causes: WPF's D3D device (software rendering in `App.OnStartup`: UI is flat gradients, video has its own window, idle CPU 0 ms and scrolling CPU unchanged) and LibVLC scanning every plugin on each start (`plugins.dat` missing, -26 MB). LibVLC never writes the cache itself, so `Player` passes `--reset-plugins-cache` when the file is absent (needs a writable app folder; otherwise it just stays slower). Do not ship a plugins.dat in the zips: it stores file times, so it has to be made where the files were extracted.
- T2 rejected: PublishReadyToRun (no change in start or memory, the app's own code is tiny), `gcConcurrent`/gen0 size/TieredPGO (no change), trimming VLC plugins (with the cache unused plugins are never loaded, so it only saves ~2-5 MB of disk; no plugin-trimming commit, nothing to revert).
- Test runs: IPTV_DATA_DIR now also gives a test instance its own mutex/pipe (SingleInstance), so a test launch can't forward its argument into the user's running window. Measured with scripts in the scratchpad, not committed.
- T3 release: two zips, self-contained win-x64 (148 MB) and framework-dependent (86 MB, needs the .NET 8 Desktop Runtime); both single-file exe plus `libvlc\` beside it (LibVLC is ~190 MB unpacked and dominates the size), no pdb. Both verified extracted to a temp folder and started from another working directory: LibVLC ready, test stream reached Playing, plugins.dat created on first run. The workflow was not run on GitHub.

- T6: renamed to YPTV (AppInfo.Name, namespace/project/folder `Yptv`, assembly `YPTV.exe`). The DPAPI entropy string, `IPTV_*` env vars and the saved-settings format are unchanged so existing data keeps working.
